# ProRiskGraph

**Дослідницький прототип попереднього аналізу документів органів місцевого самоврядування та закупівель Prozorro за ознаками потенційного корупційного ризику.**

Магістерська кваліфікаційна робота «Розробка і дослідження методики класифікації документів органів місцевого самоврядування в системі «Prozorro» з метою виявлення корупційної складової».

**Авторка:** Олена Галіцина, ЗАІ-201 · **Спеціальність:** 122 «Комп’ютерні науки» · **Університет:** Національний університет «Одеська політехніка» · **Керівник:** Марія Вороненко, к.т.н., доцент · **Рік:** 2026.

> **Призначення:** попередній відбір закупівель для експертної перевірки. Оцінка ризику, текстова категорія, адресний збіг чи сигнал можливого дроблення **не доводять порушення законодавства або корупцію**.

## Мета та можливості

ProRiskGraph поєднує опрацювання локальних PDF-документів ОМС, аналіз структурованих записів закупівель і графове представлення зв’язків у Neo4j. Прототип складається з двох модулів, які наразі виконують взаємодоповнювальні, але не повністю інтегровані операції.

- **Модуль А — документи:** вилучення тексту з PDF (за потреби OCR), розпізнавання іменованих сутностей (NER), збереження згадок у графі та перевірка адресних збігів.
- **Модуль Б — закупівлі:** завантаження даних Prozorro, обчислення базового бала за статусом і очікуваною вартістю, можливе коригування за zero-shot аналізом назви, збереження оцінок та аналіз груп закупівель на ознаки можливого дроблення.
- **Neo4j:** графове зберігання й виконання Cypher-запитів для перегляду пов’язаних записів.
- **Окремий експеримент:** нечітка модель Мамдані для дослідження агрегування показників; вона не є основним механізмом оцінювання у поточному прототипі.

## Архітектура

```text
PDF-документи ОМС                         Дані закупівель Prozorro
        |                                           |
  Вилучення тексту / OCR                     Завантаження записів
        |                                           |
  NER: особи, організації, локації       Правила: статус + вартість
        |                                           |
  Збереження згадок у Neo4j               Zero-shot аналіз назви
        |                                           |
  Графові запити / адресні збіги          risk_score та складові бала
        |                                           |
        +---------------- Neo4j --------------------+
                              |
                 Перегляд та експертна перевірка

Окремо: групування закупівель / сигнали дроблення;
         експериментальна модель Мамдані.
```

**Важливе обмеження:** автоматичне зіставлення кожного PDF-документа з конкретною закупівлею не реалізоване. Графові сигнали не додаються автоматично до підсумкового `risk_score`.

## Технології

| Завдання | Засоби |
|---|---|
| Основна реалізація | Python |
| Графове сховище та запити | Neo4j, Cypher |
| Опрацювання PDF | PyMuPDF; OCR за потреби |
| Розпізнавання сутностей | `Babelscape/wikineural-multilingual-ner` |
| Zero-shot класифікація назв | `joeddav/xlm-roberta-large-xnli`, Hugging Face Transformers |
| Джерело закупівель | Дані Prozorro |

Використані готові мовні моделі **не навчалися на власному розміченому корпусі закупівель**. Результати їх застосування потребують окремої предметної валідації.

## Як формується оцінка

У поточній реалізації нормований `risk_score` належить діапазону **[0; 1]**. Базовий бал визначається правилами для статусу та очікуваної вартості закупівлі. За визначених умов zero-shot класифікація назви може додати фіксовану семантичну надбавку. Результат зберігається разом із компонентами оцінювання та станом NLP (у версії алгоритму, описаній у дипломі станом на 07.10.2026).

`risk_score` — **показник пріоритетності перевірки**, а не статистично калібрована ймовірність корупційного правопорушення. `confidence` zero-shot моделі відображає відповідність назви заданій текстовій категорії, а не ймовірність порушення. Пошук графових зв’язків та детектор дроблення надають **окремі сигнали**.

### Нечітка логіка

У магістерському дослідженні окремо перевірено модель Мамдані на 32 збережених оцінках для зрізу **Pr = score(D), Sr = 0, Gr = 0**, а також монотонну корекцію виходу. Це перевірка властивостей обчислювальної моделі, а **не** доказ ефективності повного трьохкомпонентного агрегування на реальних закупівлях.

## Основні обмеження

1. Результати є **індикаторами для перевірки**, а не юридичними висновками.
2. Автоматичний зв’язок між кожним PDF та конкретною закупівлею не реалізований.
3. Графові сигнали не інтегровані до основного бала закупівлі.
4. Точність виявлення фактичних порушень на незалежній розміченій вибірці не встановлена.
5. NER-модель має мовні та предметні обмеження: українська не входить до переліку мов її навчального корпусу, зазначеного в дипломі.
6. Для аналізу дроблення важлива повнота відомостей про тип процедури; сигнали потребують документальної перевірки.
7. Для відтворюваності результатів потрібні фіксовані дані, версія алгоритму та параметри запуску.

## Репозиторій і запуск

У репозиторії містяться Python-скрипти опрацювання документів, завантаження закупівель, оцінювання ризику, побудови графа та демонстраційних перевірок. **Назви конкретних скриптів і команди запуску потрібно звіряти з поточною версією файлів репозиторію:** частина назв у попередньому README може відображати старі версії алгоритму.

Загальна послідовність локального запуску:

1. Встановити Python і Neo4j та створити окреме віртуальне середовище.
2. Встановити залежності з `requirements.txt` (якщо файл наявний у відповідній версії репозиторію).
3. Налаштувати з’єднання з Neo4j **без публікації пароля або токенів**; рекомендовано змінні середовища.
4. Запустити модуль завантаження закупівель та/або модуль обробки PDF.
5. Запустити класифікатор і, за потреби, окремі перевірки графа та можливого дроблення.
6. Переглянути результати у Neo4j Browser або наявному інтерфейсі прототипу.


## Наукова та практична цінність

Робота демонструє можливість спільного використання NLP, правил оцінювання та графового представлення для **попереднього відбору** закупівель ОМС. Практичний результат — відтворювані оцінки, окремі сигнали та засоби перегляду зв’язків. Наступні кроки: покращення якості NER, повноти процедурних полів, зв’язування документів із закупівлями та незалежна валідація спрацювань.
