## Що робить система

Автоматично аналізує тендери конкретного органу місцевого самоврядування (ОМС) з відкритої системи Prozorro, виявляє формальні ознаки корупційного ризику та будує граф зв'язків у базі даних Neo4j.

Методика оцінювання (розділ 2 дипломної роботи) розглядає документ як D = (T, S, G) і формує три показники ризику:

- **Pr** — структурний (бюджетний) ризик, обчислюється кусковою функцією від статусу тендера та бюджету;
- **Sr** — семантичний ризик, бінарна надбавка +0,10 при виявленні розмитого формулювання предмета закупівлі (zero-shot класифікація xlm-roberta-large-xnli, лише для тендерів > 500 000 грн);
- **Gr** — графовий ризик, бінарні маркери конфлікту інтересів (збіг адреси посадової особи й компанії-переможця в графі Neo4j).

У поточній програмній реалізації підсумковий бал обчислюється як `score(D) = min(Pr + Sr, 1.0)`; показник Gr обчислюється окремо, у складі підсумкового score поки не інтегрований (докладніше — підрозділ 2.4 диплома).

**Два функціональні модулі:**

- **Модуль А** (`module_a_documents/`) — аналіз PDF-документів ОМС: OCR + NER, побудова графу Officer → Organization → Address, виявлення конфлікту інтересів через збіг адрес.
- **Модуль Б** (`module_b_prozorro/`) — масове завантаження тендерів Prozorro, гібридна класифікація ризику (Pr + Sr), детектор штучного дроблення закупівель.

## Крок 6 — Переглянути результати

**Веб-панель:**
```bash
streamlit run dashboard_viewer.py
```
Відкриється в браузері на `http://localhost:8501`: загальна статистика графа, таблиця ризикових тендерів (`risk_score ≥ 0.70`), таблиця виявлених збігів адрес.

**Neo4j Browser** — приклади запитів:

Граф ризикових тендерів:
```cypher
MATCH (o:Organization)-[:ANNOUNCED]->(t:Tender)
WHERE t.risk_score >= 0.70
RETURN o, t
LIMIT 80
```

Топ ризиків у таблиці:
```cypher
MATCH (t:Tender)
WHERE t.risk_score >= 0.75
RETURN t.tender_id, t.title, t.budget, t.risk_level, t.risk_score
ORDER BY t.risk_score DESC, t.budget DESC
LIMIT 50
```

Кольорова візуалізація — виконати спочатку:
```cypher
MATCH (t:Tender) WHERE t.risk_score >= 0.90 SET t:HighRisk;
MATCH (t:Tender) WHERE 0.70 <= t.risk_score < 0.90 SET t:MediumRisk;
MATCH (t:Tender) WHERE t.risk_score < 0.70 SET t:LowRisk;
```
Потім у браузері клікнути на мітку `HighRisk` → встановити червоний колір.

Виявлення конфлікту інтересів (збіг адреси посадовця й компанії-переможця):
```cypher
MATCH (o:Officer)-[:REGISTERED_AT]->(a:Address)<-[:HAS_HQ_AT]-(c:Company)
RETURN o.name AS Посадова_особа, c.name AS Компанія, a.full_address AS Спільна_адреса
```

## Графова модель (схема)

```
Officer ──WORKS_AT──► Organization
   │
REGISTERED_AT
   │
   ▼
Address ◄──HAS_HQ_AT── Company ◄──WINNER_IS── Tender ──ANNOUNCED── Organization
                                                                    (замовник)
```

**Типи вузлів:** Officer, Organization, Address, Company, Tender
**Типи зв'язків:** WORKS_AT, REGISTERED_AT, HAS_HQ_AT, WINNER_IS, ANNOUNCED

Збіг вузла `Address` між `Officer` (через `REGISTERED_AT`) і `Company` (через `HAS_HQ_AT`) є формальним індикатором потенційного конфлікту інтересів.

## Методика класифікації ризику (Модуль Б)

| Статус тендера | Бюджет            | Pr    | Рівень      |
| -------------- | ----------------- | ----- | ----------- |
| unsuccessful   | > 500 000 грн     | 0.90  | 🔴 КРИТИЧНИЙ |
| unsuccessful   | ≤ 500 000 грн     | 0.70  | 🟠 СЕРЕДНІЙ  |
| cancelled      | будь-який         | 0.60  | 🟡 ПОМІРНИЙ  |
| active         | будь-який         | 0.40  | 🟡 ПОМІРНИЙ  |
| complete       | > 1 000 000 грн   | 0.80  | 🔴 ВИСОКИЙ   |
| complete       | 500 тис. – 1 млн  | 0.55  | 🟠 СЕРЕДНІЙ  |
| complete       | ≤ 500 000 грн     | 0.10  | 🟢 НИЗЬКИЙ   |

Для тендерів із бюджетом > 500 000 грн додатково застосовується NLP-аналіз назви (`xlm-roberta-large-xnli`, zero-shot). Розмите формулювання предмета закупівлі підвищує підсумковий бал на Sr = +0,10 (з обмеженням `score ≤ 1.0`).

## Можливі проблеми

**Neo4j не підключається** → відкрити Neo4j Desktop і переконатися, що база запущена (зелений індикатор).

**Помилка завантаження моделі** (`OSError: Can't load model`) → перевірити інтернет-з'єднання; модель завантажується з huggingface.co (~1.5 ГБ).

**PowerShell не дозволяє активувати venv** → `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`.

**Мало RAM — падає під час класифікації** → зменшити розмір пакета обробки в `risk_classifier.py`.

## Відомі обмеження поточної реалізації

- Показник **Gr** (графовий ризик) обчислюється незалежно від Pr/Sr і в підсумковий `score(D)` наразі не входить — Модуль А і Модуль Б функціонують як паралельні потоки (докладніше — підрозділ 2.4 диплома).
- Поле `procedure` (тип процедури закупівлі) заповнене вручну лише для обмеженої перевіреної вибірки тендерів — офіційний API не надає прямого способу довантажити це поле за публічним номером тендера.
- Довантаження даних про переможців (`add_winners.py`) для всієї вибірки з 1481 тендера ускладнене тим самим обмеженням API — перевірено на контрольованій підвибірці.
- Адреси посадових осіб для виявлення конфлікту інтересів наразі вносяться напівавтоматично (`officers.csv`) — юридичні адреси компаній-переможців, навпаки, підтягуються повністю автоматично через реєстр за ЄДРПОУ.
